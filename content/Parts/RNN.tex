\section{Some limitations of Fully-Connected Neural Networks (FCNNs)}


\begin{flushleft}
  \begin{minipage}{0.65\linewidth}
    FCNN are a cascades of matrices/non-linearities. They have some inputs and some
    output layers, interlieved by some hidden layers.
    $f(x) = \sigma(W_{out}ReLU(W_{hid}ReLU(W_{in}x)))$

    This type of models have some architectural constraints

    \begin{enumerate}
      \item The \textbf{input}/feature is expected to be \textbf{fixed} in \textbf{size}, beacuse each neurons has a specific set of weights
      \item Each \textbf{input}/feature is \textbf{associated} with its set of \textbf{weights}
      \item The \textbf{output}/feature is expected to be \textbf{fixed} in si\textbf{}ze
    \end{enumerate}

\subsubsection{The input is expected to be fixed in size}

% It is ok when is structured, such as a table. We only manage missing values.
% For unstructured and dynamic length data, such as images or text, this is not an ideal solution.

As defined by the number of columns in $W_{in}$.

\begin{itemize}
  \item \textbf{Structured data} such as a table, it is ok. We typically have fixed number of attributes, and missing values need to be handled in some way
  \item \textbf{Unstructured data} such as images or text, this is more troubling. Immages have different resolution and rations. Audios have different sampling frequencies and lenght. Text come in all lenghts
\end{itemize}



\subsubsection{Each input is associated with its set of weights}



\begin{flushleft}
  \begin{minipage}{0.65\linewidth}

    If the same pattern occurs in different portions of
    the input, the model needs to learn the same
    pattern multiple times.

    This is expensive when patterns can occur in
    multiple "places". In images, a dog is a dog, regardless of where it is.
    However, A FCNN needs to separately learn what "a dog
    is" (pattern) in each place separately:

    \begin{itemize}
      \item \textbf{Inefficient}
      \item \textbf{Data intensive} as we need a dog's picure in different places
    \end{itemize}

\subsubsection{The output is expected to be fixed in size}

As defined by the number of rows in $W_{out}$. Sometimes, we may want outputs to have
varying sizes. E.g. In object detection, we want to segment the pixels of an image

\section{Recurrent Neural Networks - RNN}

Type of NN designed to process sequential data. Can receive a sequence as input.
And/or produce a sequence as output.
RNN receives and looks at one element \footnote{Element = one unit of the sequence. E.g. a world of a sentence, a string's characters, o day of a year, etc} at a time.
And to let the model to remember what it has seen before, we add a hidden state to summarizes
the info seen so far.

\subsubsection{RNN architecture}



\begin{flushleft}
  \begin{minipage}{0.65\linewidth}

    The general RNN architecture is charaterized by
    two \textbf{inputs} and two \textbf{outputs}:

    \begin{itemize}
      \item The first input is the current element of the sequence
      \item The second input is the hidden state from the previous time
    \end{itemize}

\section{Inside an RNN}
We have three dense NN layers. Two input and two output.

\begin{itemize}
  \item \textbf{Input layer}: processes the current input,
        produces a vector with the same dimensionality as the hidden state. Makes the input
        and the state the same size dimentionality
  \item \textbf{State layer}: processes the hidden state from
        the previous step

  \item \textbf{Output layer}: Summed the two vectors and produces
\end{itemize}
